Agentic travel insurance claims · local lab

AI agents decide routine travel claims in minutes. People handle the ones that need judgement.

UnderCover is a working pilot of an AI claims platform: a customer portal, a claims handler's workspace and an AI assurance console, with Claude agents in the middle and hard limits around them.

Try it in five minutes

  1. Claim a delayed flight. In the portal, sign in as Oliver. The flight-status feed found UL 503 was 4h 40m late: tap Claim $35.00. Add a PayID on the same page. Open the portal
  2. Let the agent decide. In the handler workspace, sign in as Dana, open the new claim and press Work. Watch the case brief fill in: checks, sources and the payout. Open the workspace
  3. See it land. Back in the portal: the claim is paid to the PayID, and Updates shows the email and text we sent. Open Updates

One claim's journey

    Core concepts

    Human in the loop

    The agent pays approvals under $1,000 on its own. Anything larger waits for a senior handler's sign-off, and every decision can be overridden with a reason code.

    See the queue

    The agent decides; code pays

    Limits, payouts and the one-payment-per-claim rule live in the api, where no prompt can reach. The agent can only ask.

    Prompt-injection defence

    A hidden-instruction check reads every claim and receipt before the agent does, and refers anything that tries to give the AI orders.

    Evaluations with a held-out set

    The agent is scored against handlers' decisions on an evaluation set, and on a held-out set it never sees.

    See the scoreboard

    Self-improvement, human-gated

    An improver proposes a new configuration from the misses. An AI engineer approves it, and it's kept only if it scores better on the held-out set.

    See improvement

    Kill switch

    A senior handler can pause every payout at once. Approvals then wait for sign-off until payouts are back on.

    Three trust boundaries

    Customers, handlers and AI engineers each use their own app, sign-in issuer and token audience, so one app's token opens nothing in another.

    Context over MCP

    Policy wording, the claims manual and reference data sit in an MCP server the agent queries, with each answer's source recorded.

    Fraud signals

    Receipts are fingerprinted to find the same one on another claim, and the agent remembers a customer's earlier claims.

    Security and governance

    In the app

    • A threat model with a data flow diagram, kept with the code
    • A red-team suite of eight attack claims mapped to the OWASP Top 10 for LLM applications
    • Every agent step traced: tool calls, sources, tokens and cost
    • Receipts checked by their contents, size-limited and served only as downloads
    • Strict content security policy on every app; customer names redacted from logs

    In the pipeline

    • A secure agentic SDLC: spec, plan, threat model and review for every change
    • Semgrep, CodeQL, secret scanning and an SBOM on every pull request
    • Dependabot with a seven-day cooldown; every action and image pinned by digest
    • Protected main: changes land only through pull requests with passing checks
    • GitHub Actions deploy to AWS with OIDC, no long-lived keys (stage 2)

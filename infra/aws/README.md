# Tier 2 design

How tier 2 runs the apps on AWS: serverless in `ap-southeast-2` (decision 13). Every tier 2 piece is switched on by a setting and off by default, so `docker compose up` keeps running tier 1 unchanged (decision 13). Numbered so code and reviews can cite them (tier 2 design 6). Running and removing it: [guides/03-aws-cleanup.md](../../guides/03-aws-cleanup.md).

1. **Front ends:** each web app is built by Vite into a private S3 bucket behind its own CloudFront distribution, which forwards only that app's api prefix (`/api/customer/`, `/api/staff/` and `/api/copilot/`, `/api/engineering/`) and adds the same security headers as its nginx today.
2. **`api`, `context` and `copilot`:** the existing images run on Lambda through the AWS Lambda Web Adapter, which does nothing outside Lambda, each with a function URL that only CloudFront (or the agent) calls. The `api` migrates and seeds on start, as in Docker.
3. **`agent`:** the existing image runs on AgentCore Runtime. It adds `/invocations` and `/ping` beside its routes: `/invocations` carries the api's request (route and body, with the agent's key) to the same route, and `/ping` says busy while a claim, run, round or red team is working, so a session lasts as long as its work. The api calls it with `invoke_agent_runtime` when `AGENT_RUNTIME_ARN` is set, and over HTTP otherwise. The copilot runs on Lambda, not Runtime, because the dashboard calls it with each handler's own token; AgentCore Gateway waits until a tool needs it.
4. **Database:** PostgreSQL on Supabase (`ap-southeast-1`, decision 13) through its transaction pooler (port 6543, shared by Lambda's many short clients; no prepared statements), as `DATABASE_URL` and `CHECKPOINT_DATABASE_URL`; the Data API stays on with row-level security on every `public` table and no policies, so it serves nothing.
5. **Receipts:** a private, encrypted S3 bucket when `RECEIPTS_BUCKET` is set, under the same random names; the Docker volume otherwise.
6. **Sign-in:** three Cognito user pools (customers, staff, engineers), email and password only, each with its own app client and groups; the apps' existing issuer and audience settings point at them, and the web apps sign in to Cognito when `VITE_COGNITO_CLIENT_ID` is set. Test accounts are created by Terraform; in the demo, **Use test account** has the api sign one in through Cognito with a fresh random password it never stores (`TEST_SIGN_IN`). The project page is a fourth CloudFront site, linking to the three apps.
7. **Models:** Claude on Bedrock when `MODEL_PROVIDER=bedrock` (model ids from settings, Australian inference profile), through the same Anthropic SDK; the Anthropic API otherwise. On AWS the `MODEL_PROVIDER` repository variable chooses (Bedrock by default), and the API's key and workspace come from the app secret; configurations hold plain model names, which the agent names as its provider does. A Bedrock guardrail screens the customer's text (claims and questions), input only, before the hidden-instruction check; a block or an unreachable guardrail counts as instructions found, so a claim goes to a person and a question is refused.
8. **Secrets:** one JSON secret per environment under `travel-claims/`, read at start. Everything that can be is code: the apply generates the agent's key, records the agent's runtime ARN and leaves `SET-ME` placeholders for the two database URLs, which a person enters once; the model IDs are Terraform settings, not secrets. No secret value is in Terraform variables, images or state.
9. **Units** under `infra/aws/`, applied in order by the pipeline: `registry` (ECR), `secrets`, `storage` (receipts), `identity` (Cognito and test accounts), `guardrail` (Bedrock), `functions` (the three Lambda functions), `agent` (Runtime), `web` (buckets and CloudFront). The bootstrap's deploy role grants only what these use.
10. **Images:** a workflow builds the `api`, `context`, `copilot` and `agent` images on merge and pushes them to ECR, tagged by commit; each unit deploys the tag it's given.
11. **Done when** each unit's PR shows its plan and cost comment, applies after approval, and spec 19 holds: every app answers its health check through CloudFront, and a claim is worked end to end on Bedrock.
